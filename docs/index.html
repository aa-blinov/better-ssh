A connection is one word instead of a long ssh line.

better-ssh is a command-line tool for managing SSH connections with an interactive interface, password management and optional encryption. Every server keeps its jump chain, port forwards, environment variables and hooks. Underneath, it drives the OpenSSH client that is already on the machine.

uv tool install git+https://github.com/aa-blinov/better-ssh.git@v0.3.0

Python 3.12 or higher, uv and an OpenSSH client. Windows, macOS and Linux.

The SSH config-file arms race

If you connect to more than a handful of servers, you've felt this. IPs live in a Notion page. Passwords live in a password manager that you manually paste into the terminal. Jump hosts get re-typed. Port forwards get forgotten between sessions. Your shell history fills up with command fragments you stitched together last time.

~/.ssh/config helps, until you need more than ssh_config can express: a password that stays encrypted on disk, port forwards attached to the server rather than to the invocation, or a local aws sso login that has to run before every connect.

Before and after

Today

$ # which server was that again?
$ # let me open 1Password
$ ssh -J bastion_ops \
    deploy@prod-db.internal \
    -p 2222 \
    -i ~/.ssh/work_ed25519 \
    -L 5432:localhost:5432
# paste password from clipboard
# it's always a login shell for this one
→

With better-ssh

$ bssh prod-db
Password copied to clipboard. When prompted for Password: paste from clipboard using your terminal shortcut.
SSH: ssh -p 2222 -L 5432:localhost:5432
  -J deploy@bastion:22
  -i /home/u/.ssh/work_ed25519
  deploy@prod-db.internal
# paste, done.

Same OpenSSH under the hood. better-ssh stores what you would otherwise keep in your head.

What you get

  • Interactive picker

    A searchable menu of your servers, ordered by pinned first, then most recently used, then most used, then name.

  • Encrypted password clipboard

    Optional Fernet encryption keyed to your SSH private key, with PBKDF2-HMAC-SHA256 and a random per-installation salt. The password is copied to the clipboard on connect and never reaches the command line.

  • Jump-host chains baked in

    Name a bastion once with --jump bastion, and bssh rebuilds the full -J chain on every connect. Cycles are refused at save time, and removing a bastion clears the servers that depend on it.

  • Port forwards as server profile

    Local -L, remote -R and dynamic SOCKS -D forwards are stored with the server and passed on every connect. No more digging through shell history for the spec you built last week.

  • Parallel command broadcast

    bssh exec "uptime" prod runs the command on every matched host at once, with a per-host prefix and a summary at the end. Every matched server gets its own ssh process, which is fine up to the low hundreds of hosts.

  • Pre- and post-connect hooks

    Bring a VPN up before each connect, mount sshfs and unmount it afterwards, refresh an AWS SSO token. The commands run through your local shell, around ssh itself.

  • SSH config round-trip

    bssh isc imports your existing ~/.ssh/config through ssh -G. bssh esc writes it back out as Host blocks that ssh, scp and git read directly.

  • Scripts-friendly by design

    Every prompt has a flag, and every destructive operation has a non-interactive form: --yes, --force, --skip. Exit codes follow the Unix convention.

  • File transfer, batteries included

    bssh put and bssh get for one-shot transfers, bssh sftp for a full interactive session. The jump chain, the port and the key come from the server profile, so nothing is retyped.

Who is this for?

  • Developers juggling dev, staging and prod across several clients or VPS providers
  • SREs managing fleets of tens to low hundreds of hosts
  • Anyone whose ~/.ssh/config is longer than their ~/.bashrc
  • Anyone still pasting passwords from a password manager into terminals

If you have three servers and your muscle memory already covers them, ssh is still the right tool. No shame in it.

Get started

Install the wheel from the latest release:

uv tool install git+https://github.com/aa-blinov/better-ssh.git@v0.3.0

Import what you already have, then connect:

$ bssh isc              # imports ~/.ssh/config
$ bssh                  # the picker
$ bssh prod-db          # connect when the match is unique
$ bssh exec "uptime" prod # one command, every matching host

Every command, every flag and every edge case is in the README.
